# ZipBook — аудиокниги прямо из ZIP-архива

Android-приложение: открываешь ZIP с аудиокнигой, оно само разбирает порядок файлов,
тома и главы, и играет. Без распаковки вручную, без переименования файлов.

## Скачать

Готовый APK — на странице [**Releases**](../../releases/latest) (`app-debug.apk`).
Скачайте и установите на устройство, разрешив установку из неизвестных источников.
Это debug-сборка: ставится на любой телефон, без Google Play.

## Зачем это нужно

Ни один из распространённых Android-плееров не импортирует ZIP напрямую:

| Плеер | ZIP | Структура |
|---|---|---|
| Smart AudioBook Player | нет | папка на книгу, распаковывать вручную |
| Voice (open source) | нет | папка на книгу |
| Listen Audiobook Player | нет | автор прямо пишет: «распакуйте на компьютере» |
| Sirin | нет | сканирует папки |
| BookPlayer | **да** | только iOS/macOS, на Android нет |

Плюс две проблемы, на которых спотыкаются даже платные плееры:

1. **Порядок файлов.** Имена `00.mp3`, `0001.mp3`, `002.mp3`, `9.mp3`, `0010.mp3`
   при обычной (лексикографической) сортировке идут неправильно: `1, 10, 2`.
   Нужна «естественная» сортировка по числовому значению.
2. **Кириллица в именах внутри архива.** Русские раздачи часто упакованы в CP866 или
   windows-1251 без флага UTF-8. Библиотеки вроде `java.util.zip.ZipFile` читают имена
   одной фиксированной кодировкой и выдают «ЗЮ╬╩» вместо «Том 01».

ZipBook решает ровно это.

## Что уже работает и проверено

Проверено реальным запуском, не на словах.

**На компьютере:**

* `:core:test` — **51/51 тест проходит** (`./gradlew :core:test`)
* `:app:assembleDebug` — собирается APK ~20 МБ
* `:core:inspect` на настоящих ZIP с настоящими MP3:
  * смешанная разрядность `00 / 0001 / 0002 / 9 / 0010` → порядок `0, 1, 2, 9, 10`
  * архив с именами в **CP866** → `Лесовик / Том 01, Том 02, Том 10` распознан полностью
  * архив в **windows-1251** → то же самое
  * `Том 10` идёт после `Том 02`, а не после `Том 01`
* извлечение: 6/6 файлов полностью декодируются ffmpeg без ошибок

**На настоящем устройстве — Pixel 7, Android 17 (SDK 37), arm64:**

  (`MediaSessionStack: addSession`)
* инструментальный тест `ImportAndPlaybackTest` — **прошёл**, `failures="0" errors="0"`:
  архив с именами CP866 → 3 тома в порядке 1, 2, 10 → файлы извлечены → ExoPlayer
  отдал длительность ~3000 мс и позиция двигалась → прогресс сохранился и прочитался
  новым экземпляром `LibraryStore`
* реальное железное декодирование подтверждено логом:
  `CCodec: allocate(c2.android.mp3.decoder)`, `coded.bitrate.value = 64000`
* реальный путь пользователя (intent на ZIP) отработал: приложение показало
  «Добавлено книг: 3, глав: 6 · Лесовик — том 1 / том 2 / том 10», само записало
  `files/library.json` с правильными сериями и главами и извлекло 6 mp3
* экран библиотеки: `Лесовик` · `3 том(ов) · 6 глав` · `Том 1, Том 2, Том 10`
* воспроизведение из UI: сыграло «Главу 1», само перешло на «Главу 2» и
  остановилось в конце книги (главы в тесте по 1 секунде)
* обработка ошибок: на файл без прав доступа показан понятный диалог
  «Не удалось импортировать / open failed: EACCES», без падения
* **обложки** — инструментальные тесты 4/4, `failures="0" errors="0"`, и прямая
  проверка состояния приложения:

    записан `cover.png` ровно 20397 байт с магией `89 50 4e 47` — это байт-в-байт
    тот PNG, что был вшит в тег

    то есть картинка из архива победила тег (у дорожек тег тоже был)
  * архив без обоих источников → `coverPath: null`, `coverSource: null`

### Важное следствие из тестов на устройстве

`file://`-ссылку из другого приложения открыть нельзя — scoped storage на Android 11+
возвращает `EACCES`. Рабочие пути — это кнопка «Открыть ZIP» (SAF) и `content://` от
файлового менеджера, Telegram, браузера; именно они объявлены в манифесте. Приложение
такую ошибку не скрывает и не падает.

## Структура проекта

```
core/   чистый Kotlin/JVM, без Android — вся логика разбора, покрыта тестами
  NaturalOrder.kt     естественная сортировка (числовые пробеги сравниваются как числа)
  ZipNameDecoder.kt   восстановление имён: UTF-8 / CP866 / windows-1251 / CP437 / KOI8-R
  NameParser.kt       «Том 3», «Глава 12», «гл 7», «Vol. 2», «CD2», «01 - Пролог»
  LibraryBuilder.kt   группировка записей в книги/тома/главы + причины пропуска файлов
  CoverFinder.kt      выбор обложки среди картинок архива (приоритет имён, область поиска)
  Id3CoverExtractor.kt обложка из тега дорожки: APIC (ID3v2.3/2.4) и PIC (ID3v2.2)
  ZipReader.kt        свой парсер central directory (сохраняет сырые байты имён)
  ZipSource.kt        File или FileChannel — чтобы читать архив по дескриптору SAF
  Cli.kt              inspect/extract с компьютера

app/    Android: Compose + Media3
  data/LibraryStore.kt   состояние в одном JSON, атомарная запись через rename
  data/ZipImporter.kt    SAF Uri → разбор на месте → извлечение главы по главе
  player/PlaybackService.kt  MediaSessionService — играет при выключенном экране
  player/PlayerController.kt MediaController + сохранение позиции + artworkUri для локскрина
  ui/CoverLoader.kt      декодирование обложек с даунсэмплингом и LRU-кэшем (без Coil/Glide)
  ui/                    библиотека → книга → плеер, скорость 0.75–2x
```

## Ключевые решения

**Архив не копируется целиком.** Документ из Storage Access Framework открывается как
`ParcelFileDescriptor` → `FileChannel`, и central directory читается на месте. Серия на
несколько гигабайт иначе требовала бы двойного места только чтобы её посмотреть.

**Аудио всё же извлекается в память приложения.** Запись ZIP со сжатием DEFLATE не
поддерживает seek, а аудиокнига без перемотки бесполезна. Записи со методом STORED
помечаются флагом `stored` — на них позже можно включить проигрывание прямо из архива.

**Обложка ищется в двух местах, картинка из архива в приоритете.** Сначала
`CoverFinder` выбирает изображение среди файлов архива: имя важнее всего
(`cover`, `обложка`, `front`, `folder`), затем размер — полноразмерный скан должен
побеждать лежащую рядом миниатюру; `thumbs/`, `scans/`, `booklet/` не берутся. Если в
папке тома картинки нет, поиск расширяется к родительской папке, потому что в серии
обложка обычно одна на всё — `Серия/cover.jpg`. Если изображения нет вообще, обложка
достаётся из ID3-тега дорожки (кадр `APIC`, у старых тегов `PIC`), как это делают
настольные плееры; пробуются первые три главы, так как теги бывают не у всех файлов.
Кадр с типом 3 («front cover») предпочитается прочим картинкам в теге.

**Обложки декодируются под тот размер, в котором рисуются.** Скан 3000×3000 в полном
разрешении — это ~36 МБ heap на одну книгу, и список из таких книг был бы неюзабелен.
`CoverLoader` читает заголовок, считает `inSampleSize` и кэширует по ключу
«путь + размер», поэтому миниатюра в списке и большая картинка в плеере не вытесняют
друг друга.

**Номер главы берётся из имени только если можно доверять.** Если у всех файлов книги
есть номер и все номера различны — используются они. Иначе нумерация по позиции: иначе
два слитых диска дали бы две «главы 1».

**Числа без ключевого слова не угадываются.** `0001.mp3` даёт «голое» число, а не главу и
не том; что оно значит, решает уровень вложенности и состав папки. Поэтому `Глухарь 3`
не превращается в «главу 3», а `Tomsk 5` — не в «том 5».

## Команды

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64

# тесты логики разбора
./gradlew :core:test

# собрать APK
./gradlew :app:assembleDebug

# посмотреть, как разберётся конкретный архив (с компьютера, без телефона)
./gradlew -q :core:inspect -Pzips="/path/to/book.zip /path/to/series.zip"

# извлечь главы в порядке проигрывания и проверить их
./gradlew -q :core:inspect -Pzips="--extract /tmp/out /path/to/series.zip"
```

Установка на устройство: `~/Android/Sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk`

## Поддерживаемые раскладки архива

| Содержимое архива | Результат |
|---|---|
| `00.mp3, 0001.mp3, …` в корне | одна книга, главы по числам (`FLAT_SINGLE_BOOK`) |
| `Лесовик/Том 01/…`, `Том 02/…` | серия с томами (`SERIES_WITH_VOLUMES`) |
| `Книга А/…`, `Книга Б/…` | по книге на папку (`DIRECTORY_PER_BOOK`) |
| `Автор/Серия/Том/…` | по листовым папкам (`NESTED`) |
| файлы и в корне, и в папках | корневые — отдельная книга (`MIXED`) |

Форматы: mp3, m4a, m4b, aac, ogg, oga, opus, flac, wav, wma, mp4, mka.
Мусор архиваторов (`__MACOSX/`, `._*`, `.DS_Store`, `Thumbs.db`), не-аудио и пустые
записи пропускаются — с причиной, которая видна на экране импорта. Изображения не
считаются мусором: одно из них становится обложкой, а остальные попадают в список
пропущенных с причиной «image not used as cover», чтобы лишний скан был виден.
